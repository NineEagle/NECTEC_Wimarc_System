# บทที่ 01 — ศัพท์ 20 คำที่ต้องรู้ก่อน

> อ่าน 10 นาที

คำเหล่านี้จะโผล่ตลอดทั้งเล่ม ไม่ต้องท่อง แค่รู้ว่าหมายถึงอะไร แล้วเปิดกลับมาดูได้ตลอด
ช่องขวาสุดบอกว่าคำนั้นอยู่ตรงไหนในโปรเจกต์นี้

| คำ | แปลเป็นภาษาคน | ในโปรเจกต์นี้คือ |
|---|---|---|
| **Frontend** | ส่วนที่ผู้ใช้เห็นและกดในเบราว์เซอร์ | โฟลเดอร์ `app/`, `components/` |
| **Backend** | ส่วนที่ทำงานบนเซิร์ฟเวอร์ ไม่มีหน้าตา ทำหน้าที่ตอบข้อมูล | โฟลเดอร์ `backend/app/` |
| **API** | ช่องทางให้โปรแกรมคุยกัน — ยิงคำขอไป ได้ข้อมูลกลับมา | `/backend/stations`, `/backend/auth/login` ฯลฯ |
| **Endpoint** | API หนึ่งเส้นทาง = หนึ่งฟังก์ชันฝั่ง backend | ปัจจุบันมี 64 เส้นทางใน `backend/app/main.py` |
| **JSON** | รูปแบบข้อความที่ใช้ส่งข้อมูลระหว่างเครื่อง | `{"air_temperature": 31.2, "vpd": 1.42}` |
| **HTTP method** | ประเภทคำขอ: GET = ขอดู, POST = สร้างใหม่, PUT = แก้, DELETE = ลบ | ใช้ครบทั้ง 4 แบบ |
| **Status code** | เลขตอบกลับ: 200 สำเร็จ · 401 ยังไม่ล็อกอิน · 403 ไม่มีสิทธิ์ · 404 ไม่เจอ · 429 ยิงถี่เกิน · 500 พังฝั่งเซิร์ฟเวอร์ | เห็นได้ในแท็บ Network ของเบราว์เซอร์ |
| **Database (DB)** | ที่เก็บข้อมูลถาวร เป็นตารางเหมือน Excel แต่ใหญ่และค้นเร็ว | PostgreSQL 16 — มี 2 ชุด (บทที่ 09) |
| **SQL** | ภาษาสั่งฐานข้อมูล เช่น `SELECT * FROM users` | ใช้ตรง ๆ ตอนอ่านตารางเซนเซอร์เดิม |
| **ORM** | ตัวแปลงระหว่างตารางในฐานข้อมูลกับ object ในโค้ด จะได้ไม่ต้องเขียน SQL เอง | SQLAlchemy ใน `backend/app/models.py` |
| **JWT / Token** | บัตรผ่านที่เซิร์ฟเวอร์ออกให้หลังล็อกอิน แนบไปกับทุกคำขอเพื่อบอกว่าเราคือใคร | เก็บในเบราว์เซอร์ชื่อ `wimarc_token` อายุ 24 ชั่วโมง |
| **localStorage** | ที่เก็บข้อมูลเล็ก ๆ ในเบราว์เซอร์ ปิดแล้วเปิดใหม่ยังอยู่ | เก็บ token + ข้อมูลผู้ใช้ที่ล็อกอินอยู่ |
| **RBAC** | การแบ่งสิทธิ์ตามบทบาทผู้ใช้ | 3 บทบาท: Admin / User / Guest |
| **Repo (repository)** | โฟลเดอร์โปรเจกต์ที่เก็บประวัติการแก้ไขทุกครั้งด้วย git | `/var/www/WiMaRC` |
| **Commit** | การบันทึกการแก้ไขหนึ่งชุดลงประวัติ พร้อมข้อความอธิบาย | ดูได้ด้วย `git log --oneline` |
| **Build** | การแปลงโค้ดที่คนอ่านรู้เรื่อง ให้กลายเป็นไฟล์ที่เครื่องรันเร็ว | `pnpm build` / `docker compose build` |
| **Docker / Container** | กล่องปิดที่บรรจุโปรแกรมพร้อมทุกอย่างที่มันต้องใช้ ย้ายเครื่องแล้วรันเหมือนเดิม | ระบบนี้มี 2 กล่อง: `frontend` กับ `backend` |
| **Image** | แม่พิมพ์ของ container — build ครั้งเดียว เอาไปรันกี่กล่องก็ได้ | สร้างจาก `Dockerfile.frontend.prod` และ `backend/Dockerfile` |
| **Reverse proxy** | ตัวรับคำขอจากอินเทอร์เน็ต แล้วส่งต่อให้โปรแกรมข้างในที่ถูกตัว | Apache รับพอร์ต 443 แล้วส่งต่อไปพอร์ต 3000 |
| **Environment variable (env)** | ค่าตั้งต้นที่ไม่เขียนลงโค้ด เช่นรหัสลับ ที่อยู่ฐานข้อมูล | ไฟล์ `.env` ที่รากโปรเจกต์ (ห้ามขึ้น git) |

## คำที่คนมักสับสน

**`pnpm` กับ `npm`** — ทำหน้าที่เดียวกันคือติดตั้งไลบรารีฝั่ง JavaScript แต่โปรเจกต์นี้ใช้ `pnpm`
เท่านั้น (เวอร์ชัน 9.12.3 ล็อกไว้ใน Dockerfile) ถ้าเผลอใช้ `npm install` จะได้ไฟล์ `package-lock.json`
โผล่มาเกินและเวอร์ชันไลบรารีอาจไม่ตรงกับที่ทดสอบไว้ — **ห้ามใช้ npm**

**`app/` กับ `backend/app/`** — ชื่อเหมือนกันแต่คนละโลก
`app/` (รากโปรเจกต์) คือหน้าเว็บทั้งหมด เขียนด้วย TypeScript
`backend/app/` คือโค้ดฝั่งเซิร์ฟเวอร์ เขียนด้วย Python

**"deploy" กับ "build"** — build คือแปลงโค้ดให้พร้อมรัน, deploy คือเอาผลลัพธ์นั้นขึ้นไปให้ผู้ใช้จริงใช้
ในระบบนี้สองอย่างนี้อยู่ติดกัน: `docker compose build` แล้วตามด้วย `docker compose up -d`

## จำ 1 ประโยคนี้ให้ได้

> **เบราว์เซอร์ไม่เคยคุยกับฐานข้อมูลโดยตรง**
> เบราว์เซอร์คุยกับ frontend → frontend คุยกับ backend → backend เท่านั้นที่คุยกับฐานข้อมูล

ถ้าจำได้ประโยคเดียวนี้ ทุกอย่างในบทถัดไปจะเข้าที่ และเวลาเจอปัญหาคุณจะรู้ว่าต้องไล่หาทีละสถานี
ไม่ใช่เดามั่ว
